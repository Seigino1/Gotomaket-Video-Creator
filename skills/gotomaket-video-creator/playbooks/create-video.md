# Playbook: 从输入到产品宣传片

## 目的
输入产品地址或文件，通过多轮对话输出可信、符合品牌且可播放的宣传视频及工程。

## 前提条件
- 至少一个可访问的产品仓库、官网、本地目录或用户文件；不能访问时只分析可访问材料，明确缺失。
- 可写独立目录；先检查已有工程和用户决定。
- 渲染前所选引擎、浏览器、字体、FFmpeg/FFprobe 和本地资源可用。

## 步骤
1. 产品理解：读仓库规则、README、版本、组件/接口或官网核心页；文件用对应文档工具解析。保存来源、版本/日期、定位、用户、流程、卖点和验证等级到 `evidence/product.json`。不从代码提交推断上线。
2. 首轮对话：先给产品理解和推荐故事，再问未确定的受众、渠道、语言；最多三个问题。仅官网也能制作，不强求源码。保留逐字脚本；得到改写授权才重组。
3. 导演与脚本：按阶段提示词组织“问题/目标 → 操作 → 可见结果 → 行动”，给推荐方向和一到两个明确备选。写 `BRIEF.md`、`DIRECTION.md`、`SCRIPT.md`，说明模板如何来自产品。
4. 工程：依据引擎参考选择。直接调用 `scripts/init_project.py` 创建独立目录；已有工程不重建。调用 `scripts/doctor.py`，只补缺项，固定依赖版本并保留 lockfile。把分析文件保存到工程。
5. 计划：按契约填 `plan.json`，引用证据和本地资产，完善所有语言，改 `demo=false`。镜头用整数帧连续覆盖全片。调用 `scripts/validate_plan.py --production`；`state.json` 保存阶段和确认决定，可断点继续。
6. 视觉：从真实产品提取品牌和交互状态；React 组件在隔离工程挂载，用固定脱敏 fixture。仅截图时忠实表现截图和取景；重建片段标记示意。输出首帧、密集画面和 CTA 静帧后继续动画。
7. 动效：按 Prompt Motion 适配查一到三个参考，保存 URL、作者、手法和 Codex 实现说明。生成素材优先宿主订阅当前已有能力；用户选择 Higgsfield 增强才进入其 Playbook，默认不开付费 API，无额度用已有素材和代码图形继续。
8. 语言/声音：独立文案、UI、旁白、字幕；实测音频长度安排窗口。素材优先用户提供或可用工具，音效对齐动作、音乐让位。调用 `scripts/export_captions.py`。
9. 出片：关键帧 → 短样片 → 完整输出。运行媒体检查，看联系表、转场两侧和末帧，播放各语言并试听。修复后重新导出受影响版本，旧 bundle 不能验收新代码。
10. 交付：MP4、字幕、封面、脚本、工程、lockfile、计划、证据与 `DELIVERY.md`。自动检测、视觉审查、试听和未验证项分别记录，返回实际文件链接。

## 判断标准
- 用户“先方案” → 等反馈后完整渲染；“直接制作” → 用已说明默认值继续，无需每阶段确认。
- 仅官网 → 官方陈述与真实截图；仅文件 → 材料依据，不扩展无关网站。
- React 组件 → Remotion；HTML 动效 → HyperFrames；无法复用 → 记录边界和重建片段。
- 翻译/配音长于镜头 → 先精简措辞，再调整停留，不机械加速；共用时轴变动同步各语言。
- 长文或字幕遮挡 → 重排、缩短或取景，不无限缩小字体。
- 动效表达对象、动作、业务结果；装饰运动不能代替演示。末段是否持续运动由导演意图决定。
- 某片 58 秒、业务案例、进度位置与透明度属于项目决定，不作为所有影片固定规则。
- 环境/账户故障属于 D 类，修前提并继续可完成步骤。

## 验证
- 所有卖点关联证据；技术样片与虚构数据不冒充生产结果。
- 镜头、字幕、旁白、音效和实际文件一致；各语言无意外残留。
- 首帧与 CTA 完整，界面可读，转场无空白、资源闪失和字幕裁切。
- MP4 解码通过，工程与字幕存在，播放/试听记录可追溯。
